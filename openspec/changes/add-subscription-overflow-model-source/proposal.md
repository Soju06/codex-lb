## Why

When every eligible subscription account has exhausted its usage limit, codex-lb can only answer `429 usage_limit_reached`. Issue #2123 designs an operator-designated model source that absorbs that overflow at its own cost while subscription routing stays untouched. The design lands in stages; this change carries the schema stage first so the migration sits alone on the Alembic graph and the behavioural stages can build on a settled data shape without re-parenting. The routing stage (WP-C2, with the WebSocket parity of WP-D folded in by owner decision) completes the change: overflow routing is now specified and shipped, dark until an operator designates a source.

## What Changes

- Add two nullable `dashboard_settings` columns: `subscription_overflow_source_id` (the designated source; no foreign key, a dangling id means "off" like `single_account_id`) and `subscription_overflow_drain_until` (the deadline armed when a designation is cleared so pinned conversations can drain).
- Add the `model_source_pins` table (`pin_key` primary key, `kind`, `source_id` without a foreign key, nullable `api_key_id`, timezone-aware `created_at` / `last_seen_at` / `expires_at` / `purge_at`) with the `ix_model_source_pins_purge_at` index.
- One Alembic revision, `20260908_000000_add_subscription_overflow`, on the current head: idempotent against a partially applied schema, fully downgradable, identical logical schema on SQLite and PostgreSQL.
- **Designation settings (WP-B, inert).** `PUT /api/settings` accepts a tri-state `subscription_overflow_source_id` (absent = unchanged, `null` = off, value = designate) that only accepts an OpenAI-compatible source with Responses support (else `400 subscription_overflow_source_invalid`); clearing it arms the read-only `subscription_overflow_drain_until` deadline (`now + 29 d`), designating clears the deadline, and every write invalidates the settings cache across replicas. Deleting the designated model source clears the designation and arms the deadline in the same transaction as the delete.
- **Preflight (WP-B).** `GET /api/settings/subscription-overflow/preflight?source_id=` reports, for a source, whether it can be designated and what an operator should fix first: served vs missing registry models, models that can never overflow (Responses-Lite / code mode), undeclared Codex tool types, vision, streaming, pricing, context-window mismatches, source-scoped API keys, and live/tombstone pin counts. Only the kind/Responses checks block. The dashboard's Routing card gains the designation select, the inline preflight, and the help text; `docs/routing.md` gains the operator explainer.
- **Overflow routing (WP-C2 with WP-D folded in), shipped dark.** On `/backend-api/codex/responses` and `/v1/responses` the proxy decides once at route admission -- after model and tier enforcement, before any reservation, lease, bridge session or byte -- whether an exhausted subscription pool should overflow to the designated source: read-only probe (`usage_limit_reached` only; drain strategies never trigger), closed declines (opportunistic or source-scoped keys, binding turn state, background jobs outside `review`/`compact`/`collab_spawn` or any memory-generation request, non-portable bodies), designated-source resolution, telemetry-stripped body with `service_tier` removed, portability verdict, then the per-source concurrency slot and breaker token as the last await-free step. Every decline falls through to today's `429 usage_limit_reached` byte for byte, except a `not_portable_history` hint (`x-codex-promo-message` for native Codex, an `error.message` sentence for SDKs). A conversation that received source content is pinned by `thread-id` and anchored by source `response.id` in one transaction verified durable before the first content frame; pinned and anchored turns route to their source regardless of pool state, fail closed with `503` (transient) or `400` (permanent) and are released to subscription only when the transcript is provably source-free after a durable delete. Per-source breaker (3 failures / 30 s / one leased half-open trial) and bulkhead claims are released by exactly one latch. WebSocket: handshakes deny with `426` only on pin, tombstone or bounce evidence; fresh exhaustion during a session gets an in-band `503 model_source_requires_http_transport` event with top-level `status` plus a 60 s bounce row; the HTTP bridge never enters overflow. Compaction on a pinned conversation is refused with `400`. Rows are attributed to the source (`source` `subscription_overflow` / `subscription_overflow_pinned`, `requested_service_tier`, `service_tier` null, estimates never written as usage). Requests to sources carry only proxy-constructed headers. **Ship-dark guarantee:** with both settings columns `null` the request path performs two attribute reads and one comparison and no probe, lookup, selection, claim or body walk -- an exhausted pool and a served stream are byte-identical to a deployment without the feature; the production designation is gated on this release being deployed with anchors and WebSocket parity wired, and the canary is a separate deployment with its own database (no per-replica flag).

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `database-migrations`: the dashboard-settings and pin schema for subscription-exhaustion overflow is represented by ORM metadata and a single-head Alembic revision.
- `model-source-routing`: operators designate a subscription-overflow model source through the settings API and dashboard (tri-state, eligibility-validated, drain deadline, cleared by source deletion) and read a non-blocking preflight for it; durable thread-keyed pins with verified writes; the admission-time overflow decision, pinned/anchored routing with fail-closed answers and neutral release, the per-source breaker and admission claims, source attribution, proxy-constructed source-direction headers, and the ship-dark rollout with its canary drills.
- `responses-api-compat`: source-routed bodies stripped of Codex telemetry; provider-portability classification with closed decline reasons; one Responses lifecycle per overflow dispatch and its closed error-code set; byte-identical declines with the history hint; WebSocket `426` on evidence and the in-band bounce; pinned compaction refused.
- `account-routing`: the read-only pool-exhaustion probe with selection parity, the overflow trigger being its answer, and the drain-strategy exclusion.
- `proxy-runtime-observability`: the owned-once dispatch row, the model-source and overflow metrics (closed label sets), the breaker and live-pin gauges, and the overflow log names.
- `api-keys`, `outbound-http-clients`, `data-retention`: live limited-key source streams with the settle-at-estimate policy, the bounded and isolated source transport, and the unconditional pin prune (WP-C1).

## Impact

- `app/db/models.py` (two `DashboardSettings` columns, the `ModelSourcePin` model), one new Alembic revision, migration tests (WP-A).
- `app/modules/settings/*` (schemas, service, repository, API, the new dashboard-only `subscription_overflow.py`), `app/modules/model_sources/api.py` (delete hook), the dashboard Routing card (`frontend/src/features/settings/*`, i18n en/ko/zh-CN), `docs/routing.md` (WP-B).
- New dashboard setting `subscription_overflow_source_id`: defaults off and cannot be a default because it names an operator-owned paid source. No `CODEX_LB_*` environment variable, README section, or navigation item.
- Proxy: `app/modules/proxy/overflow.py` (decision, breaker, claims, fast-decline, hint, compaction and handshake checks), `app/modules/proxy/api.py` (two route insertions, the route-helper latch, non-stream pin commit, compact and handshake hooks, the 429 hint), `app/modules/proxy/_service/websocket/overflow.py` plus two mixin call sites, the C1 modules' interface patches (`source_admission.py`, `source_dispatch.py`, `model_source_pins.py`, `replay_safety.py`), `app/core/metrics/prometheus.py` (overflow counter, breaker gauge) and `app/core/retention/job.py` (live-pin sampling). The inertness ratchet becomes a positive ratchet naming the allowed importers and call sites. No CLI or configuration surface changes: no `CODEX_LB_*` variable, no per-replica flag; the fleet-wide designation is the only switch and is off by default.
- Dashboard: the staged-rollout notice under the designation control is removed (en/ko/zh-CN together); the request-log chip, `source` filter and cost tile land with WP-G. `docs/routing.md` gains the shipped status, the flip gate, the WebSocket and hint behaviour, the observability names and the canary drill list.
