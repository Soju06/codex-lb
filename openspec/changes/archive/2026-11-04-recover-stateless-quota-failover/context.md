Codex Responses requests in this path are stateless when they carry no stored conversation, previous-response or prompt anchor and no account-owned hosted resource. A quota error before any downstream-visible output permits the unchanged request to be attempted on a different eligible account. The proxy does not remove or reinterpret compaction ciphertext, reasoning ciphertext, tool inputs or outputs, local agent messages, metadata or future inline item types. File, container, vector-store, stored hosted-tool and MCP approval references remain pinned. A declared MCP server or inline MCP or computer result is not by itself evidence of an account-owned reference. Any rejection by the replacement account is returned under the existing error handling; this change does not assume all providers use the same encryption keys.

Some older Codex session keys have a hard affinity row. For a stateless turn, the row must not override a quota failover or prevent first dispatch when its old account is unavailable. After these conditions arise, the selector switches to soft cache affinity, subject to the same account-scoped resource, explicit owner and routing safeguards. This does not relax owner-bound bridge or WebSocket retry policies.

For example, if a tool output contains an empty text part, the part is forwarded unchanged instead of preventing account migration. If the first five accounts report quota exhaustion, selection may continue to the sixth. A request containing a `file_id` does not cross accounts.

Isolated tests exercised failover and a real upstream continuation using synthetic input. The response retained markers from the synthetic compaction and agent history, and the input remained identical across retries. Additional targeted tests checked continuation across accounts. These observations apply to the tested upstream and do not establish universal cross-provider ciphertext portability.

No production conversation data, credentials or account identifiers are included in this change. The retry path preserves existing API-key reservation and account-health settlement ordering. The 64-account bound does not increase the original retry budget for unrelated failures.
