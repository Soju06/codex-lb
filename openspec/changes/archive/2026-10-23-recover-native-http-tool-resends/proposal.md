## Why

A complete HTTP tool-loop resend can remain stuck on a rejected upstream response anchor because native metadata and completed assistant commentary fail the existing account-neutral context classifier. The original history is safe to retain on its verified durable owner without making it portable across accounts.

## What Changes

- Recognize complete, response-manifest-verified native tool loops in the HTTP bridge's owner-bound context proof.
- Preserve the original input, reasoning, compaction, metadata, instructions and cache identity on fresh connections and bounded stale-anchor recovery.
- Prevent implicit fallback and owner retirement from moving an owner-bound request to another account.
- Keep account-neutral eligibility, agent-message support, quota policy and ordinary WebSocket behavior unchanged.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `responses-api-compat`: owner-bound HTTP recovery for complete native tool histories.

## Impact

HTTP bridge context validation, focused route and proof regressions, and the owning specification. No new settings, migrations, dependencies or UI changes. Related PR #2581 handles agent-message suffixes; #2617 handles prefix-settled account-neutral outputs. This change addresses neither and does not depend on them.
