## Why

Production Responses SSE streams occasionally reach the client with a full-looking body but no terminal frame (`response.completed` / `response.failed` / `response.incomplete` / `error`), while `request_logs.status` says `success`. Status is settled when the proxy *parses* the upstream terminal frame (`terminal_event_seen = True` is set before the terminal `yield` in the streaming service), not when the frame is *written* downstream, and nothing in the stack records whether the write happened. Two write paths lose the frame silently: uvicorn's `RequestResponseCycle.send` returns without writing once the cycle is marked disconnected (a peer FIN/RST racing the terminal write), and an exception raised by an `api.py` stream wrapper while formatting the terminal block closes the inner generators after settlement. The ASGI `receive()` channel cannot discriminate either case because it reports `http.disconnect` after every normal completion too. Today the truncation rate is not measurable.

## What Changes

- **Protocol-side disconnect stamp.** `app/core/http_protocol.py` gains `HTTP_DISCONNECTED_STATE` and `stamp_disconnect_into_scope(cycle, exc)`; both production protocol subclasses (`UpgradeTolerantHttpToolsProtocol`, `UpgradeTolerantH11Protocol`) call it from `connection_lost` after the stock teardown. When a connection is lost while a response is still in flight, the loss kind (`eof` or the exception type name) is written into that request's existing ASGI `scope["state"]` dict. Under HTTP/1.1 pipelining uvicorn's httptools implementation replaces `self.cycle` with the newest parsed request and queues it in `self.pipeline` while the earlier response is still streaming, so the httptools subclass additionally tracks the cycle whose ASGI task is running (`_start_asgi_task`) and stamps every open request on the connection — active, newest and queued (h11 keeps a pipelined follow-up unparsed until `start_next_cycle`, so its `self.cycle` is already the active one). Completed responses are never stamped; no new reference or transport side effect is added.
- **Traced streaming response.** New module `app/modules/proxy/downstream_delivery.py` with `DeliveryTracedStreamingResponse(StreamingResponse)`. It wraps the ASGI `send`, counts chunks/bytes, detects the terminal SSE event type on `event:` lines (anchored match at the block start plus a `bytes.find` prefilter for further line starts — never a regex walk over a large frame — across a rolling tail buffer so frames split across chunks are still recognised), commits the terminal only once the complete block — `event:` line through the blank-line terminator — was handed over and the server's `send` returned for the chunk carrying the terminator (uvicorn drains write backpressure before writing, so a cancel inside `send` means no write; a disconnect or cancellation between the `event:` line and the terminator is therefore never reported as a written terminal), and reports exactly one bounded outcome per stream: `terminal_written`, `terminal_after_disconnect`, `exception_before_terminal`, `cancelled_before_terminal`, `ended_without_terminal`. Emission is one `responses_stream_terminal_delivery` log line (DEBUG for `terminal_written`, INFO for `cancelled_before_terminal`, WARNING otherwise) and one increment of the new counter `codex_lb_stream_terminal_delivery_total{surface,outcome}`. Forwarded bytes, request-log status and settlement are untouched; no synthetic frame is ever emitted.
- **Wiring.** `_stream_responses` in `app/modules/proxy/api.py` returns the traced response (`surface="responses"`), which covers the native codex HTTP path, the HTTP session bridge, and the per-request WS-upstream variant. Other `StreamingResponse` sites are out of scope.
- **Metric registration.** `stream_terminal_delivery_total` in `app/core/metrics/prometheus.py` with the usual `None` fallback when `prometheus_client` is absent.

No new `CODEX_LB_*` setting, no `.env.example` change, no migration, no README growth, no growth of any ceiling-guarded proxy file. The trace is default-on like every existing counter and no-ops without `prometheus_client`. Observational only: it does not change any forwarded byte or any settlement decision. No issue is attached; this PR exists to make the truncation rate measurable before any fix is attempted.

## Join key

The log line's `request_id` is the ingress request id (`RequestIdMiddleware` contextvar). The streaming service stores that value in `request_logs.archive_request_id`; `request_logs.request_id` is overwritten with the upstream response id once `response.created` was seen. Ops joins therefore go through `archive_request_id` (see `context.md`).

## Deferred (documented, not implemented)

- **Settlement ordering.** Reordering `terminal_event_seen = True` after the terminal `yield` is *not* a safe fix: it would flip these rows to `cancelled` / `client_disconnected` and make the retry layer skip terminal settlement, under-counting consumed usage. Any settlement change needs its own responses-api-compat change once the trace shows how often each outcome occurs.
- **Wrapper-exception hardening** (fall back to the raw terminal block when a wrapper raises while formatting it) is deferred until `exception_before_terminal` is observed in production.
- Opting other SSE surfaces into the traced response.
- **`data:`-only terminal frames.** The detector keys on `event:` lines, matching how every emitted block is framed (`format_sse_event`). The one raw passthrough (`preserve_raw_sse_line`, upstream `error` frames on the native codex path) relays the upstream line verbatim; if upstream ever ships an `error` frame without an `event:` line, settlement would record `error` while the trace reports `ended_without_terminal`. A sustained `ended_without_terminal` count is the signal to extend the detector.

- Affected specs: `proxy-runtime-observability` (ADDED trace metric/log requirement, next to the existing streaming metric contracts), `responses-api-compat` (MODIFIED settlement wording), `http-ingress-limits` (ADDED disconnect stamp requirement, key `codex_lb.http_disconnected`).
- Affected code: `app/core/http_protocol.py`, `app/core/http_protocol_httptools.py`, `app/core/metrics/prometheus.py`, `app/modules/proxy/downstream_delivery.py` (new), `app/modules/proxy/api.py` (one return site + import).
- Tests: `tests/unit/test_downstream_delivery.py` (new; includes split-terminal-block commitment and disconnect/cancellation inside a split frame), `tests/integration/test_http_disconnect_stamp.py` (new; includes pipelined fake-transport and live-socket regressions where the queued request had replaced `self.cycle`), two real-app tests appended to `tests/integration/test_proxy_responses.py` (wiring of `_stream_responses`; `scope["state"]` identity through the full middleware stack).
