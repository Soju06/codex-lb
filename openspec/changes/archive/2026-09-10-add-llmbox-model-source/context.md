# Local integration design

The native `/v1/responses` endpoint responds with a standard response object and usage. `auto-max` is a dynamic gateway route: the initial trivial test reported `deepseek_v4_flash`; this does not establish Astra availability. TRAE/Coco agents remain under managed-bots and are not used as model API substitutes.

Use the existing source kind column; an explicit llmbox kind grants access only to the server user's normal `~/.llmbox/cache/accesstoken`. UI creation is opt-in and initially disabled. Fixed origin validation occurs both on writes and immediately before forwarding, protecting against stale or manually edited rows. Redirects must not transfer credentials to another host. Upstream company errors are reduced to a stable generic envelope so a rotated credential cannot leak through reflection.

Usage is an observed retained-log window, not billing history. No platform quota API is currently verified. Docker deployments need an intentional read-only cache mount under the server user's home; a cache on the desktop is not automatically available inside containers.

Validation runs against isolated state/ports. The active account pool and `127.0.0.1:2455` routing are not modified. This change does not assert full Codex capability parity merely from a text response.
