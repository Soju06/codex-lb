## 1. Schema and dependency

- [x] 1.1 Add `pyjwt[crypto]>=2.13.0` to `pyproject.toml` and regenerate `uv.lock`. The floor is not the oldest working release: `< 2.12.0` accepts unknown `crit` header extensions and `< 2.13.0` carries the unbounded Base64URL payload-segment decode and the public-key-as-HMAC-secret key confusion, all three against `jwt.decode`, which is the only entry point used here. Its only new transitive dependency is `cryptography`, already direct. `jwt.PyJWKClient` is not used anywhere: it fetches with blocking `urllib`, no timeout, no size bound and no host validation.
- [x] 1.2 `DashboardAuthProvider.test_login_user_id` (`String(36)`, FK → `dashboard_users.id` ON DELETE SET NULL, nullable) and `test_login_verified_at` (`DateTime(timezone=True)`, nullable); new model `DashboardOidcLoginFlow` (`state_hash` `String(64)` primary key, `provider_id` FK → `dashboard_auth_providers.id` ON DELETE CASCADE, `nonce_hash` `String(64)`, `code_verifier_encrypted` `LargeBinary`, `purpose` `String(16)`, `acting_user_id` FK → `dashboard_users.id` ON DELETE CASCADE nullable, `redirect_uri` `String(512)`, `config_fingerprint` `String(64)` (the digest of the connection document the flow was started against), `created_at`, `expires_at` indexed).
