# Policy and limits

The server reevaluates company availability at each catalog request; desktop clients may cache lists and require refreshing/reconnecting. A leader-only scheduler issues a minimal `Reply with exactly OK.` request per enabled model every two hours. The probe requests at most eight output tokens and has a 30-second deadline; some providers do not enforce the requested output cap, so actual usage is recorded and may be higher. Providers run in parallel while models sharing a provider run sequentially, respecting the configured per-source concurrency limit. An in-progress probe does not erase the last completed health result. Listing itself never spends inference tokens.

A successful probe must complete within 30 seconds and remains fresh for three hours, leaving one hour of scheduling grace beyond the two-hour cadence. Unknown, stale, failed, or slow models are hidden. Operator settings retain all models. Probe usage is persisted and contributes to the source's local token budget because it consumes real provider resources.
