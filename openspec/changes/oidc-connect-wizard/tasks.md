## 2. The card and its dialog

- [x] 2.1 `oidc-card.tsx`: `<section id="oidc" className="scroll-mt-16 …">` in the reverse-proxy card's shape (icon header, `AlertMessage` slot under it, controls below). States: no stored connection → "Connect company sign-in"; stored and off → saved-not-on with the pre-flight and a disabled turn-on control; on → the label, the issuer, the verification state, an edit control and a turn-off control that is never gated. Reads `provider` and `mutations` from the body like its siblings; calls no permission hook of its own.
- [x] 2.2 `oidc-connect-dialog.tsx`: three steps. (a) issuer, discovery URL (optional, placeholder naming the well-known default), client id, client secret, redirect URI pre-filled from `window.location.origin` + the callback path and copyable. (b) subject/email/name/groups claim names, each optional with its default as the placeholder. (c) the pre-flight. Client-side validation of everything `OidcConfigRequest` would reject (required, `https`, redirect-URI suffix, 512/256 lengths) because those answer `422 validation_error` with no `param`. It runs on the values `configFrom` will send, so every field it trims is validated trimmed: a client id of nothing but spaces is refused inline rather than sent as the empty string, and padding the wizard strips anyway is not a refusal. `clientSecret` is the exception, being the one field sent verbatim.
- [x] 2.3 One `PATCH {config}` on leaving step (b), `mutateAsync(...).catch(() => undefined)` with no optimistic mirror, then a re-read of the row. The secret is component state only: never in storage, never in a URL, never re-sent from the mask, and never in a query cache — which the shared `updateOidcProvider` mutation would otherwise break on its own, since a settled mutation keeps the `variables` it was called with and that hook belongs to the group rather than to the dialog. `save` resets it once the write settles, either way, and the mutation carries `gcTime: 0` so the detached state leaves the cache instead of lingering.
- [x] 2.4 Inline refusals: `invalid_provider_config` against the field `refusedOidcField` names, on the step that shows it; `config_not_supported` and `insufficient_delegation` on the dialog; `oidc_test_login_required` on the turn-on control; `oidc_provider_unreachable` and `oidc_rate_limited` on the pre-flight panel that provoked them — the start answers both, so neither can land on the connection fields a step earlier; the `429` names its wait and retries nothing. ## 3. The pre-flight window

- [x] 3.1 `frontend/src/features/auth/oidc-window.ts`: `openFlowWindow()` called synchronously in the activation handler (blank window first, location assigned when the start answers, closed if the start is refused); `null` → record the marker and navigate the current tab. Marker in `sessionStorage`: `{providerId, purpose, verifiedAt}`, single-use on read, nothing else ever written.
- [x] 3.2 The return hook, imported by the app shell so it runs before the settings page paints: this origin + the server's settings or failure destination → announce the return on a same-origin `BroadcastChannel` and, when an opener is still there, post to it and `window.close()`. The opener accepts the posted message only for `event.origin === window.location.origin` and `event.source === handle`; the broadcast carries no origin check because nothing else can address the channel. Both are "ask the server again", never a verdict. With no opener the hook answers `false` and lets the app mount rather than betting on `window.close()` for a window the identity provider disowned.
- [x] 3.3 The severed-handle rule, which is why the broadcast exists: an identity provider serving `Cross-Origin-Opener-Policy: same-origin` on `/authorize` (Entra ID does) takes the opener link away for the rest of the flow, so `handle.closed` turns true half a second after the start. The poll therefore clears itself and re-reads *without* ending the watch — the return signals and the ten-minute deadline stay — and the card shows the "did not finish" copy only for a terminal end. The channel is closed in teardown.
- [x] 3.4 Arming: re-read `GET /api/auth-providers` on every return signal and arm iff `testLoginVerifiedAt` advanced past the value observed at the start. In-memory only; cleared by a connection write, by a successful enable and by a reload.
- [x] 3.5 Same-tab failure return: with a marker in flight, a signed-in session at `/login` goes to `ORGANISATION_SETTINGS_RETURN_URL` instead of the dashboard (`signedInLoginDestination()`, which reads the marker without consuming it — the card is what spends it — and one `Navigate` target in `App.tsx`).

## 6. Not this change

- [x] 6.1 `step-up-dialog.tsx`: the `methods: ["oidc"]` branch is **already shipped**, by #2411, and this change neither touches the file nor restates its requirement. What landed there is not §3's window flow: the dialog settles the interrupted request as *not verified* and navigates the whole page to the authorization URL, because nothing can replay a request across a page load and the person repeats the action after the callback returns. That is what `oidc-provider-backend`'s "Re-authentication at the identity provider is a step-up factor for an account that has no other" requires, so a second copy here would have been a conflicting one. Nothing to do.
- Deferred to a follow-up change — **one rules card per company sign-in provider**: `companyLoginProviders(providers)`, a card per provider with a stored connection naming its own provider and writing its own `provider`/`providerKey`, and the refused sign-ins header on the first card only because the audit read is not filtered by provider. It is a second concern with its own write path and its own tests, this change ships no part of it, and the `Group-to-role rules card` delta therefore stays as `role-mappings-and-organization-group` wrote it (one card, the reverse-proxy row's rules) plus the masked address the sheet now shows. Until it lands, the one card the group renders is the reverse-proxy row's and writes that row's `provider`/`providerKey`, so the OIDC row's rules have no surface at all — which is the gap the follow-up closes, not a promise this change may make.
